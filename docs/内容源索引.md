# 内容源索引

本文件只记录**元信息**（有什么、在哪、怎么用），不含原文。

「锚点」的产品内核来自两个内容源。它们的位置、数量和授权边界如下。

## 一、两个内容源

| 内容源 | 形态 | 数量 | 本地位置 | 授权 |
|---|---|---|---|---|
| Huberman《Protocols：人体操作手册》 | 47 条协议，每条含 WHAT TO DO / WHAT NOT TO DO | 47 条 | `docs-internal/内容源/Huberman-Protocols-47条.md` | **有版权**（z-library 副本），**不进公开仓库** |

原件压缩包（Protocols.rar、高性价比人生指南.rar）同在 `docs-internal/内容源/压缩包/`。

## 二、留档方式

- 两个内容源已**完整留档在一个独立的本地 git 仓库**里（`docs-internal/`，与公开仓库分开，远端为私有仓库 `gin996hhh/vibe-coding-internal`）。
- 文件被误移走、误删，都能从该仓库的 git 历史恢复。
- 公开仓库 `gin996hhh/vibe-coding` 里**只有本索引文件**，不含任何原文。

## 三、它们在产品里怎么用

三环结构各接一个内容源（详见 `产品理念-2026-10-02.md`）：

- **状态环（身体状态）** ← Huberman 47 条协议。用户打卡的睡眠 / 精力 / 心情三个 1–5 分，用来选对应状态下该做什么。
- **方法环（具体做什么）** ← 《高性价比人生指南》650 条。按成本标签筛选，其中「毅力 = 否」的有 337 条——这一批是状态低时也能做的，优先推。
- **频率环（做多少次）** ← 产品自身的交互次数设计，不依赖外部内容源。

《高性价比人生指南》可以光明正大地放进产品、写进文档、署作者名。

Huberman《Protocols》只能在本地用——**不要把原文贴进公开仓库、公开页面或作业正文**。要用它的内容，用自己的话重述成产品里的指导语。
