## 调用 01（Day 12）

- **时间**：2026-09-30
- **调用方式**：读取项目内 `.workbuddy/skills/frontend-guidelines/SKILL.md`，按其六类规则逐条核对
- **检查对象**：`records.html` 的「每天」列表区（`#dayList`）+ 即将新增的筛选控件（关键词输入框、完成状态下拉、清空按钮）

### 调用前提示词

> 按项目内 frontend-guidelines 检查记录台的列表区，我要在这一块加一行筛选控件（关键词搜索 + 完成状态筛选 + 清空）。
> 告诉我：新增控件在层级、颜色、字号、间距、按钮状态、360px 宽度上各要遵守什么，以及我原样写法会被它拦下哪几条。

### Skill 给的约束（适用于本次改动）

| 规则类 | 本次相关的一条 |
|---|---|
| 页面层级 | 筛选控件属于「每天」卡片内部，不能自己升一级标题；区块靠间距分组，不靠分隔线 |
| 颜色 | 色值只能来自 `css/style.css` 的 `:root`；`--ember` 暖橙只给「已完成 / 做到」，筛选控件一律蓝灰 |
| 字号 | 正文 16px、次级 14px、三级 13px；**任何可见文字不低于 12px**（输入框默认字号常小于 16px，要显式写） |
| 间距 | 只取 8 / 12 / 16 / 22 四档；卡片内边距 18px；不许出现 10、11、15 这类随手值 |
| 卡片与按钮 | 输入框必须有可见 focus 样式；按钮要有默认 / 悬停 / **禁用**三态 |
| 移动端 360px | 360px 下不许横向滚动；触控目标高度 ≥ 40px；导航小屏允许换行 |

### 检查结论（问题清单）

检查的是**待新增**的控件，所以清单是"必须满足什么"，实现后逐条对照：

1. 输入框字号：浏览器默认 `<input>` 字小于 16px → 必须显式给 16px，否则同时违反「正文 16px」和「不低于 12px」
2. 输入框 focus：现在项目里没有输入框先例 → 必须新建 `:focus` 可见样式，否则违反「输入框必须有可见 focus 样式」
3. 清空按钮禁用态：无筛选条件时按钮应不可点 → 复用 `css/style.css` 已有的 `button:disabled`（Day 11 补的），不许新造样式
4. 筛选行在 360px：输入框 + 下拉 + 按钮一行放不下 → 允许换行，但触控目标 ≥ 40px
5. 结果计数：命中数量属于次级信息，用 `.muted`（14px），不承担主要信息
6. 空结果文案「没有找到相关内容」：属于状态反馈不是报错，用 `.muted`，**不许用 `--danger`**（报错才用 danger）

### 调用前后差异（这一条是必做证据）

| | 不调用 Skill 的原样写法 | 调用后的写法 |
|---|---|---|
| 颜色 | `<input style="border:#3a4a63">` 内联写死色值 | 新增 CSS 类，色值全部取 `:root` 变量 |
| 字号 | 用浏览器默认字号 | 显式 16px |
| 间距 | `margin: 15px 0` 随手值 | 取 8 / 12 / 16 / 22 档 |
| 按钮 | 清空按钮始终可点 | 无筛选条件时 `:disabled`，复用已有禁用态 |
| 反馈 | 空结果用红字 | 空结果用 `.muted`，`--danger` 留给真报错 |
| 移动端 | 一行塞三个控件，360px 挤爆 | 换行 + 触控目标 ≥ 40px |
